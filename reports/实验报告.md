| 项目 | 内容 |

## 1. 结论摘要

**基线定义说明**：配置里的 `augmentation.baseline_level` 是 `weak`，因此
"基线"= 共享六头 + sigmoid + 交叉熵 + SGD(μ=0.9, lr=0.05, bs=64) + **弱增强**。
下表如实给出该基线，以及 E7 发现的最优配置（`aug_none`）。两者架构与
优化超参数完全相同，**唯一差别是数据增强**。

1. **同分布测试集**：基线（共享六头 + 弱增强）字符准确率 **86.8%**、整牌
   准确率 **43.4%**（3 种子均值）；把增强关掉后（E7 `aug_none`）同分布字符准确率提升到
   **98.4%**、整牌 **91.8%**。**后者是本项目的最优同分布结果**，且是在
   3 个随机种子上稳定复现的（±0.08 / ±0.40）。
2. **六个独立 MLP 反而优于共享隐层**（E1）：测试字符 94.3% vs 86.8%，
   整牌 72.6% vs 43.4%，**合成域字符 66.9% vs 43.3%（+23.7 pt）**。原因是独立
   架构参数量约 6.3M，是共享架构 1.10M 的 **5.8 倍**，容量差距压过了共享带来
   的正则收益；代价是 CPU 单张推理耗时从 0.375 ms 涨到 1.934 ms（**5.2 倍**）。
3. **交叉熵显著优于平方误差**（E3）：mse 前 20 轮 val_loss 下降慢一个量级
   （见 §7.4），最终整牌准确率也明显更低。
4. **批量大小是决定性的**（E4，统一 2000 张口径）：batch=32/64/128 都能收敛，
   **128 最优**（测试整牌 27.95%），而 **batch=1（纯 SGD 逐样本更新）
   完全不收敛**：跑满 35 轮后验证字符准确率始终卡在 **20%**、整牌恒为
   **0.00%**，验证损失在 43–81 之间震荡。根因是逐样本梯度方差随 `1/B`
   放大（B=1 时是 B=64 的 8 倍），固定 `lr=0.05` 下有效步长被噪声放大
   （§7.5）。
5. **数据增强在本架构上是负面的**（E7）：none > weak > strong 呈严格单调，
   测试整牌 91.8% → 43.4% → 2.4%，合成域字符 **44.5% → 43.3% → 22.4%**（同向）。
   原因是 MLP **没有平移/尺度不变性**，
   几何增强把字符挪到训练时没见过的像素位置，等于给模型注入噪声而不是
   正则（§7.8 有逐算子拆解证据）。
6. **纯 SGD（μ=0, lr=0.01）优于动量基线**（E5）：测试字符 89.1% vs 86.8%、
   整牌 45.5% vs 43.4%，且种子方差小一个量级；动量臂早停提前 ~22 轮触发
   （§7.6）。
7. **更强的 L2（λ=1e-3）全面最优**（E6）：测试字符 89.1%、整牌 50.4%、
   方差最小；模型处于欠拟合区，L2 的收益来自稳定优化而非压制过拟合（§7.7）。
8. **relu 在固定 lr=0.05 下完全失败**（E2）：死亡 ReLU——隐层预激活被
   推向 −110，99.5% 激活恒零，模型退化为边缘分布预测器；同 lr 降到 0.01
   即恢复正常（78.1%）。lr 必须与激活函数联合调（§7.2）。
9. **输入分辨率不是瓶颈**（E8）：24×96 与 32×128 统计打平
   （整牌 42.4% vs 43.4%），参数量省 42%、CPU 推理快 15%（§7.9）。
10. **输出头的位置先验免费白捡整牌准确率**（E9）：首位约束 24 类后
    整牌 46.6% vs 43.4%（+3.2 pt），参数量还略降（§7.10）。
11. **跨域差距显著但可控**：合成域测试集改用外部开源生成器
    （`Nenger/chinese_licence_plate_generator` @43bac43 的牌面级输出）后，
    基线模型在该域的字符准确率为 **43.3%**（34 类随机猜测 2.9%），比同分布
    测试集低 **43.5 个百分点**；独立架构在同一合成域上达 **66.9%**。
    已验证这不是实现 bug：合成图清晰可读、标签与图像 2000/2000 一致、
    六格字符质心与真实域偏差 ≤2 px（§8）。**旧版内置渲染器合成集上的
    "≈5%、基本等于乱猜"结论已作废**——差别来自新集合的构造（上游字形素材
    取自实拍车牌裁切、蓝底模板 + 上游扰动链），详见 §8.3。
12. **BP 与损失实现正确**：数值梯度校验通过（8 份产物覆盖 sigmoid/relu ×
    双架构 × 34×6/194 节点，0 项失败）；小样本过拟合自检达到 loss < 1e-3
    且字符/整牌 100%（§5）。

> **本报告中的"负结果"是刻意保留并解释的**：E7 表明我最初设定的增强强度
> 对本架构过强，E4 表明逐样本 SGD 在本数据规模下不可用。这两点都按实测
> 数据如实报告（而不是把配置调到好看再报告），并在 §7.8 / §7.5 给出机制
> 层面的解释。

### 2.2 数据准备（§2）

* **只做切分，不做检测**（§0.3 禁止）：车牌区域**仅**由 CCPD 文件名里
  标注的四个角点确定。文件名解析见 `models/ccpd_parse.py`。
* **透视矫正**用 `PIL.Image.PERSPECTIVE` + `numpy.linalg.lstsq` 求系数
  （**不使用 OpenCV**）。
* 几何流程：矫正到 **168×52** → 裁掉左侧首位汉字（保留右 6/7，`crop_x0=24`）
  → 缩放为 **128×32** → 灰度 → `[0,1]`。
* **不做汉字识别**（§0.3）：首位汉字区域直接裁掉，标签只含后 6 位。
* **标准化统计量只在训练集上拟合**：mean=**0.421204**、std=**0.221177**、
  n=**9000**。测试集/验证集/合成域都复用这套统计量，避免用评测数据反推
  训练参数。
* **数据目录是扁平的，子集名在文件名里**（**不按子目录组织**）：
  `data/ccpd/` 下直接平铺 30000 张 jpg，子集名以
  `_ccpd_<subset>_<序号>.jpg` token 追加在文件名尾部，由
  `models/ccpd_parse.py::extract_subset` 解析；图片发现用
  `models/dataset.py::discover_images` 的 `rglob` 递归扫描，所以用子目录
  组织也能跑，但**判定子集只看文件名 token**。实测分布：`ccpd_base` 14987、
  `challenge` 4077、`tilt` 2504、`blur` 1845、`fn` 1822、`green` 1179、
  `rotate` 1050、`db` 1035、`weather` 1021、`np` 480（合计 30000）；
  其中 `green`/`np` 被丢弃，`db` 入缓存但不落入任何集合（详见 README §3.1）。

数据来源与保留情况：

| 项 | 值 |

### 2.4 三类测试集

| 集合 | 构造方式 | 用途 |
|---|---|---|
| **同分布 test** | CCPD-Base 随机划分，与训练同源同风格 | 主指标 |
| **强扰动 hard_test** | CCPD 的 blur / challenge / rotate / tilt / weather / fn 等困难子集 | 检验鲁棒性 |
| **合成域 synth_test** | **外部开源生成器** [Nenger/chinese_licence_plate_generator](https://github.com/Nenger/chinese_licence_plate_generator)（固定 commit `43bac43`）的**牌面级**输出，再套用**同一套几何裁剪** | 检验跨域泛化 |

合成域构造要点（`train/synth_from_generator.py`，后端 `synth.backend=generator_repo`）：

1. 直接调用上游 `FakePlateGenerator.generate_one_plate()` 生成**完整 7 位牌面**
   （首位省份汉字照常渲染，随后被同样裁掉），渲染尺寸即本项目 `rectify_size`（168×52）；
2. 施加该仓库自带的扰动链：`jittering_color` → `add_noise` → `jittering_blur`
   → `jittering_scale`（与其示例完全同序；`jittering_scale` 先缩后放回原尺寸，
   只损失清晰度、不改变几何）；
3. 走与 CCPD 完全相同的几何管线：裁掉左侧 1/7（`crop_x0=24`）→ 缩放为
   128×32 → 灰度 → `[0,1]`；
4. **上游字符素材含字母 I、O**，而本项目字符集排除 I/O（§2.1），因此逐张校验
   标签合法性并**拒绝重采**（2000 张共拒绝 912 张，拒绝率 31.3%）；
5. 固定种子 `seed=2024`（同步播种 stdlib `random` 与 `np.random`），生成器
   commit 号写入 `split_summary.json` 的 `synth_config` 与 `manifest.csv` 的
   `source_file` 字段（形如 `generator_repo:43bac43:2024:<i>`）。

> **为什么不入内置渲染器而用外部生成器**：本项目不做车牌检测（§0.3），因此
> 不使用该仓库主打的"车牌贴进街景图"整图产物，而用其牌面级接口——这是上游
> 自带的用法（见其 `fake_plate_generator.py` 的 `__main__`）。早期版本的
> 内置 PIL 渲染器代码保留（`train/synth_plates.py`），可经 `synth.backend`
> 切回，但**不再是报告口径**。

合成域与强扰动集**只用于测试，从不参与训练或调参**。

## 3. 模型与损失（§3）

### 3.1 结构

```
输入 x: (N, 4096)          # 32×128 展平
   │
   ├─ 共享隐层： z1 = x @ W1 + b1 ;  h = sigmoid(z1)      W1:(4096,256), b1:(256,)
   │
   └─ 6 个独立 Softmax 头： logits_i = h @ W2_i + b2_i     W2_i:(256,34), b2_i:(34,)
        输出 (N, 34) × 6，共 204 个输出节点
```

* 参数量：4096×256 + 256 + 6×(256×34 + 34) = **1 101 260**。
* 字符集 34 类 = 数字 `0-9` + 大写字母去掉 `I`、`O`（共 24 个），
  与 CCPD 官方 `ads` 表顺序一致（索引 0–23 为字母、24–33 为数字）。
* `model.arch` 另有 `independent` 变体（E1）：6 套完全独立的隐层，
  参数量 6 345 420。

### 3.2 损失

总损失 = **6 路 Softmax 交叉熵之和 + L2**：

```
L = Σ_{i=1..6} CE(logits_i, y_i)  +  λ · (‖W1‖² + Σ_i ‖W2_i‖²)
```

* 交叉熵用稳定写法（先减最大值再 `log-sum-exp`），防上溢。
* **偏置不参与 L2 惩罚**（`loss.penalize_bias: false`）。
* `λ = 1e-4`。
* E3 的对照变体把 6 路交叉熵换成 6 路平方误差（MSE over softmax 输出）。

### 3.3 优化器（手写）

* SGD + 动量 0.9，`lr = 0.05`，`batch_size = 64`，最多 80 轮。
* 早停：监控 `val_loss`，patience=8，`min_delta=1e-5`。
* **保存最佳验证模型**（`save_best_only`），训练结束后回滚到最佳权重再评测。
* 全部梯度由手写的 `models/model.py::backward` 解析推导，**没有任何框架
  自动求导**（§8）。CuPy 只用来加速矩阵乘法。

## 4. 复现方法（§8.4）

```bash
# 0) 环境
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt

# 1) 数据准备（下载 → 解析 → 矫正裁切 → 缓存）
python train/phase1_prepare.py

# 合成域测试集需要外部生成器仓库（不入库，固定 commit 43bac43）
git clone https://github.com/Nenger/chinese_licence_plate_generator data/external/chinese_licence_plate_generator
python train/synth_from_generator.py      # 生成 40 张预览 + 人工核对网格（§2.4）

python train/phase15_split.py

# 2) 正确性自检
python train/grad_check.py          # 数值梯度校验
python train/overfit_check.py       # 小样本过拟合自检

# 3) 训练与实验
python train/train.py --name baseline_s42 --seed 42
python reports/run_all.py --only E1 E3 E4 E7 --baseline --skip-existing

# 4) 独立评测（不重新训练，只载入检查点）
python evaluate/main.py --run baseline_s42

# 5) 出图与报告表格
python reports/make_figs.py --runs baseline_s42
python reports/rebuild_summary_tables.py   # 由 logs/*_run.json 重建汇总表（不训练）
python reports/make_split_bar_figs.py      # 由汇总表重画各测试集变体对比图（不训练）
python reports/build_report_tables.py --write --inject
```

> **合成域切换后本报告数值的来历（只重测、不重训）**：合成域测试集从内置
> 渲染器切换为外部生成器时，训练集/验证集/同分布测试/强扰动集**完全未变**
> （手术式替换只改划分文件里的 `synth_*` 三个数组，`train/val/test/hard`
> 索引与标准化统计量逐字节校验不变，见 `train/swap_synth_to_generator.py`），
> 且合成域**从不参与训练或调参**（§2.5 要求 3）。因此本轮**没有重训任何
> 模型**：`reports/refresh_synth_eval.py` 用各运行的**最佳检查点**在新合成域上
> 重测（口径与 `train/train.py` 训练末评测相同：同一 `evaluate_dataset`、
> 同一 `eval.batch_size` / loss / L2 配置），刷新 `*_run.json` 的
> `synth_test` 字段与全部评测产物。非合成域数值在重测后与历史**逐位一致**
> （已抽查 `baseline_s42` / `E1_independent_s42` / `E8_size_24x96_s42` 等），
> 可据此确认重测链路无误。

每次运行的日志/CSV/JSON 都带这些字段，缺一不可作为最终结论：

| 字段 | 含义 |
|---|---|
| `commit` | 训练时的 git commit |
| `config_fingerprint` | 生效配置的 sha1 指纹（含变体补丁之后） |
| `seed` | 随机种子 |
| `dirty` | 工作区是否有未提交改动；`true` 的结果原则上不作为最终结论（见下） |

> **关于本报告各运行的 `dirty=true`**：本项目的实验与报告/工具链是并行
> 推进的，多数运行落盘时工作区还有未提交改动，因此该字段普遍为 `true`。
> 这不等于"结果来自不可追溯的代码"：每轮实验对应的代码与产物在当阶段
> 结束时**一并提交**（见 §1 的 commit 记录），且做了两道交叉验证——
> ① 同种子复跑校验（`reports/logs/repro_check.json`，同种子两次训练权重
> 逐位一致）；② 本阶段修复（mask 进反向 / monitor 方向 / 越界标签防线，
> 见 §5.4）在干净工作区提交后，以原配置原种子**复跑基线并与既有产物逐位
> 比对**（§5.5）。两道都通过，故 `dirty=true` 的历史运行仍可作为结论依据。

## 5. 正确性自检

### 5.1 数值梯度校验（BP 是否正确）

方法：中心差分 `(L(θ+ε) − L(θ−ε)) / 2ε`，ε=1e-6，float64，随机数据 8 个
样本，对共享层与 6 个头的权重/偏置每类张量抽查 3 个分量（全尺寸模型：
hidden=256，输入 4096）。

| 检查项 | 结果 |
|---|---|
| 架构 | shared 与 independent 各查一次 |
| 精度 | **float64** |
| shared（34×6，sigmoid） | 相对误差最大 **5.31e-07**，绝对误差最大 3.31e-09，失败 0 项 |
| independent（34×6，sigmoid） | 相对误差最大 5.52e-06，绝对误差最大 3.81e-09，失败 0 项 |
| shared / independent（relu） | 相对误差最大 5.67e-07 / 1.21e-06，失败 0 项 |
| shared / independent（E9：194 节点 + 首位掩码路径） | 相对误差最大 2.65e-07 / 3.48e-06，失败 0 项 |
| 判据 | 相对误差 < 1e-5 **或** 绝对误差 ≤ 1e-8 |

> **为什么用 float64**：总损失量级约 22，ε=1e-6 时损失变化只有 ~1e-7，
> 低于 float32 的分辨率，数值梯度会退化成纯粹的量化噪声（相对误差≈1）。
> 这不是 BP 推导错，而是差分本身在 float32 下不可用。
>
> **为什么 relative 误差有 1e-6 量级**：中心差分在 float64 下的相消误差
> 下限约为 `|L|·ε_machine/h ≈ 4e-9`；当某些被抽查分量的梯度本身只有
> 1e-3 量级时，相对误差自然落到 1e-6。因此判据用"相对 **或** 绝对"双阈值，
> 两个判据满足其一即通过——这与数值优化的通用做法一致。
>
> **E9 掩码路径为什么单独校验**：E9 把首位压到 24 类，训练时首位为数字的
> 样本通过 `head_mask` 被排除出首位头的损失。实现早期 mask 只作用于损失、
> 没有同步进手写反向（损失/梯度不一致），该校验在该结构下必然 FAIL；
> 修复（`backward_*` 增加 `head_mask` 形参）后两侧严格一致，上表即证据。

原始记录：`reports/logs/grad_check_shared.json`、`grad_check_independent.json`
（relu 版带 `_relu` 后缀，E9 版带 `_e9_194` 后缀，共 8 份）。

### 5.2 小样本过拟合自检（损失/BP 是否可用于学习）

100 个样本、纯 SGD（μ=0）、lr=0.5，要求 loss < 1e-3 且字符/整牌 100%。

| 项 | 结果 |
|---|---|
| 达到 loss < 1e-3 的轮次 | **18000 / 20000** |
| 实测 loss | **9.594e-04** |
| 字符 / 整牌准确率 | 100% / 100% |
| 结论 | **PASS** |

> **为什么需要 20000 轮**（实测标定，非实现 bug）：总损失是 6 路交叉熵之和，
> 要 < 1e-3 意味着每一路都要压到 ~1.7e-4；而 sigmoid 隐层输出被限在 (0,1)，
> 把某类概率推到 1−1e-4 只能靠把输出层权重范数推大，因此损失按 ~O(1/轮)
> 衰减。
>
> **关于动量的更正**（本阶段补测推翻了旧结论）：本文档早期声称"μ=0.9 会
> 把损失卡在 ~2e-2 的极限环"。补测（100 样本、lr=0.5、numpy、seed=42，
> `reports/logs/overfit_check_mu09_lr05_20k.json`）显示：μ=0.9 是**慢速
> 单调下降**并在 **11000 轮**达到 1e-3，比 μ=0 的 18000 轮**更快**；
> "卡在 2e-2"只是 400 轮观察窗内的错觉。本自检仍保留 μ=0 默认值（它确实
> 达标且轨迹与历史产物逐位一致），但"动量导致小样本不收敛"的说法**不成立**。
> 动量在真实训练中的真实代价见 §7.6（E5：早停提前触发、最终精度更低）。
> 记录：`reports/logs/overfit_check.json`、`overfit_check_mu09_lr05_20k.json`。

## 7. 对照实验（E1–E9）

全部实验都用 **3 个随机种子 [42, 43, 44]** 重复，表中为 `mean ± std`。
**除已注明者外**，正文引用的数字均为 3 种子均值（若个别处引用了单种子值，

### 7.1 E1 —— 共享六头 vs 六个独立 MLP

<!-- TABLE:E1:BEGIN -->

**E1 共享六头 vs 六个独立 MLP**

| 变体 | 种子数 | 平均轮数 | 测试集字符 | 测试集整牌 | 强扰动字符 | 合成域字符 | 参数量 |

**结论**：独立架构在**同分布**与**强扰动**上都更好，且 3 个种子上稳定：

| 指标 | shared（1.10M） | independent（6.35M） | 差距 |
|---|---|---|---|
| 测试字符准确率 | 86.82 ± 1.76% | **94.30 ± 0.48%** | +7.5 pt |
| 测试整牌准确率 | 43.43 ± 6.49% | **72.55 ± 1.75%** | +29.1 pt |
| 强扰动字符准确率 | 62.25 ± 1.87% | **69.75 ± 1.12%** | +7.5 pt |
| 合成域字符准确率 | 43.26 ± 3.05% | **66.92 ± 0.82%** | **+23.7 pt** |
| 合成域整牌准确率 | 0.35% | **4.63%** | **+4.3 pt** |
| 参数量 | 1 101 260 | 6 345 420 | **5.8×** |
| CPU 单张推理 | 0.23–0.39 ms | **1.934 ms** | **5–8×** |
| 平均训练轮数 | 58.3 | 35.3 | 独立架构收敛更快 |

**原因分析**：共享隐层强迫 6 个位置共用同一组底层特征，在数据量只有 9000
时是一种强正则，但容量成了瓶颈——共享架构**欠拟合**（训练字符 88.8%），
而独立架构训练字符 95.1%（3 种子均值；s42 单种子 95.8%），明显更贴合训练分布。独立架构给每个位置各自的
256 维特征空间，容量足以拟合位置特异的外观差异，因此同分布准确率大幅提升，
且标准差更小（更稳定）。

**两点重要补充**：

1. 独立架构**收敛更快**（35.3 轮 vs 58.3 轮就触发早停），说明它不是在
   "多花时间"，而是"同样时间学得更多"。
2. 两者在**合成域**上的差距（43.3% vs 66.9%，+23.7 pt）与同分布上的差距
   方向一致，说明**容量与位置特异表征同样决定跨域表现**：独立架构给每个
   位置各自的 256 维特征空间，能容纳"同一字符在不同位置/不同字形间距下的
   外观差异"，因此在字形几何与真实域并不完全一致的外部合成域上也明显更强。
   换言之，**跨域差距不只是"外观分布不可迁移"这一项**——仅凭旧版内置渲染器
   合成集（两架构都 ≈5–6%）得出的"容量解决不了跨域问题"的判断，在改用外部
   生成器后不再成立，已按新证据更正（§8）。

`grad_check_independent_relu.json`，max_rel = 5.67e-07 / 1.21e-06）。

**机制证据（死亡 ReLU）**：用 `train/diag_relu_death.py`（可重跑，
输出 `reports/logs/relu_death_diag.json`）解剖训练后的 `E2_relu_s42`
检查点发现——

| 状态 | 隐层"死亡单元"比例 | z1（预激活）均值 | h==0 的（样本×单元）比例 |
|---|---|---|---|
| 随机初始化 | 0.0% | +0.04 | 49.0% |
| 训练后（lr=0.05） | 6.2% | **−110.7** | **99.5%** |

即预激活在前几个 epoch 被爆炸式更新推向极大负值（均值 −110！），
隐层对 99.5% 的输入恒输出 0；此后 relu 的梯度恒为 0，参数**永远无法恢复**，
模型退化成只剩 b2 偏置在学"各位的边缘分布"——这正好解释
22% ≈ 边缘众数频率、训练损失 ≈ 16.6–16.7 这个平台（6 路边缘熵之和实测
15.84，其余差额来自 L2 正则项与偏置尚未完全贴合边缘分布的余量）。

**根因**：sigmoid 的导数 ≤ 0.25，会把隐层梯度衰减约 4 倍；relu 的导数是 1，
不衰减。因此同一份 lr=0.05（叠加 μ=0.9 后有效步长 0.5）对 relu 而言
等效于 4 倍过热。

**补充探针**（`e2lr_relu_lr001_s42`，非 E2 正式口径）：同一结构把 lr 降到
0.01 后，relu 正常学习，测试字符 78.12%、整牌 21.05%。所以准确的结论是：
**relu 不是"不行"，而是 lr 必须与激活函数一起调**；在规格固定的
lr=0.05 下，sigmoid 是正确选择。另外 relu@lr=0.5（过拟合自检口径）直接
发散到 NaN，同样印证"lr 对 relu 过热"（`reports/logs/overfit_check_relu.json`）。

|---|---|---|
| 首次达到 80% 验证字符准确率 | **第 16 轮** | 第 37 轮 |
| 第 20 轮验证字符准确率 | **81.62%** | 75.47% |
| 最终验证字符准确率（最佳权重） | **86.59%** | 81.52% |
| 最终测试整牌准确率 | **43.43%** | 24.42% |

> 以准确率为主、loss 仅作参考的原因。

乘一个 `p(1−p)` 因子。当预测错得很离谱时（正确类 `p ≈ 0`），`p(1−p) ≈ 0`，
梯度被压得极小，出现"学不动"的假死现象——这与实测的"mse 前 20 轮慢一倍"
完全吻合。整牌准确率差距（43.4% vs 24.4%）比字符准确率差距（86.8% vs
82.7%）大得多，因为整牌要求 6 位全对，**每位的微小差距会被连乘放大**。

> **口径说明（重要）**：E4 的 5 个变体在**统一的 2000 张训练子集**上比较
> （`--limit 2000`），运行名带 `e4n_` 前缀。原因是 `batch_size=1` 的每次
> 参数更新只用一个样本，在 9000 张上**每轮约 100.7 秒**（纯前向+反向+更新
> 实测，`train/diag_bs1_timing.py` → `reports/logs/bs1_epoch_timing.json`；
> 含逐轮验证与日志的完整训练轮还要更久），
> 跑满 80 轮需要约 2.2 小时/种子，3 个种子不可承受。
>
> 统一到 2000 张后，`batch_size=1` 每轮约 **26.1 秒**，可以在时间预算内
> 跑到足够轮数。**同一实验内所有变体用同一份数据**，因此该对比是公平的；
> 但它与 E1/E3/E7 的 9000 张口径不同，跨实验比较时需注意。

**吞吐量实测**（每轮参数更新次数 = 样本数 / batch_size；2000 张口径的耗时
区间为 s42 单运行逐轮值，3 种子合并池会略宽；含逐轮验证与日志）：

| batch_size | 每轮更新次数（2000 样本） | 每轮耗时（实测区间） | 每轮更新次数（9000 样本） | 每轮耗时 |
|---|---|---|---|---|
| **1**（纯 SGD） | 2000 | 25.5–26.9 s（均值 26.1） | 9000 | **100.0–101.4 s**（纯训练实测¹） |
| 32 | 63 | 1.25–1.65 s | 282 | 未单独实测 |
| 64（基线） | 32 | 0.96–1.43 s | 141 | 4.32–5.67 s（baseline_s42 实测） |
| 128 | 16 | 0.75–1.04 s | 71 | 未单独实测 |
| 全批量(-1) | 1 | 0.58–1.07 s | 1 | 未单独实测 |

¹ bs=1 的 9000 张口径只测了纯"前向+反向+更新"（`train/diag_bs1_timing.py`
→ `reports/logs/bs1_epoch_timing.json`，11.1–11.3 ms/次）；含逐轮验证的
完整训练轮会略长。其余未实测格按更新次数约为 2000 张口径的 4.5 倍外推。

**为什么 `batch_size=1` 不稳定（机制解释）**：

设单样本梯度为 `g_j`，批梯度是 `g = (1/B) Σ g_j`。若单样本梯度方差为 `σ²`，
则批梯度方差约为 `σ²/B`，**标准差约 `σ/√B`**。B=1 时梯度噪声标准差是
B=64 时的 **8 倍**。配合 `momentum=0.9`（把有效步长放大 `1/(1−μ)=10` 倍），
等效步长被噪声进一步放大，参数在最优点附近被推得很远。

实测现象与推断一致（`e4n_E4_batch_1_s42`，跑满 35 轮后被早停）：

| 轮次区间 | val_loss 范围 | 验证字符准确率 |
|---|---|---|
| 第 1–5 轮 | 72.00 – 81.23 | 19.73 – 21.16% |
| 第 10–20 轮 | 52.59 – 61.32 | 18.19 – 21.36% |
| 第 25–35 轮 | 43.56 – 53.70 | 13.22 – 21.17% |

35 轮下来字符准确率始终在 **20% 左右徘徊**（34 类随机猜测是 2.9%，所以它
只学到了"字符大致是什么"的边缘分布；注意第 30 轮附近还有一次下探到
13.2% 的深谷，随后弹回——这正是逐样本噪声把参数反复推离优点的直接表现），
验证损失在 **43–81 之间剧烈震荡**，整牌准确率恒为 **0.00%**。
对比同期 `batch_64` 的曲线是**单调平滑下降**。

注意它**并不是发散到 NaN**，而是被噪声永久锁在一个高损失平台，这在优化上
叫"高方差下的临界稳定"。想让逐样本 SGD 真正工作，必须把学习率按其梯度噪声
量级相应调小（经验上随 `1/√B` 缩放）——这也正是 `optim.learning_rate`
注释写着"搜索 {0.01, 0.05, 0.1}"的原因。

**批量大小的完整排序（2000 张统一口径，3 种子均值）**：

| batch_size | 测试字符 | 测试整牌 | 强扰动字符 |
|---|---|---|---|
| **128** | **82.35 ± 0.62%** | **27.95 ± 1.11%** | **60.84 ± 0.53%** |
| 64 | 77.79 ± 0.71% | 19.52 ± 1.94% | 56.00 ± 0.23% |
| 32 | 68.03 ± 2.41% | 7.30 ± 2.26% | 47.50 ± 1.25% |
| 全批量(-1) | 64.17 ± 1.36% | 1.58 ± 0.34% | 48.79 ± 1.11% |
| **1** | **21.20%** | **0.00%** | 19.20% |

**规律**：在本配置的 `lr=0.05` 下，准确率随批量增大而**单调上升直至
batch=128**，随后全批量因为每轮只更新一次（2000 样本 1 次更新）而掉下来。
也就是说本实验里最佳批量是 **128**，而**批量 32 反而比 64/128 差** ——
这与"小批量泛化更好"的常见说法相反，原因是本实验的**学习率没有随批量
一起调**：批量越小、梯度噪声越大，固定 `lr` 下有效步长越失控。

> 这也说明"小批量泛化更好"这个经验结论的前提是**学习率随批量做过缩放**
> （线性缩放或平方根缩放）。本项目按规格要求把 `optim.learning_rate` 固定为
> 0.05，因此观察到的是未做缩放时的原始趋势。若把批量调小同时按 `1/√B`
> 下调 lr，排序很可能发生改变——这是一个明确的后续实验方向。

> **口径与偏差说明**：E4 统一用 2000 张训练子集，所以表中绝对值低于
> E1/E3/E7 的 9000 张口径（例如 batch_64 在同口径下测试字符 77.79%，
> 而在 9000 张口径下是 86.82%）。**E4 的结论只在"批量之间的相对排序"
> 上成立**，不用于与其他实验比绝对值。

**结论**：
1. 小批量 32–128 都能正常收敛，**128 在本配置下最优**；
2. **逐样本 SGD（bs=1）在本数据规模与 lr 下不可用**：不收敛、整牌恒为 0；
3. 全批量能收敛但慢（每轮仅 1 次更新），80 轮下来仍落后于 128；
4. 批量的选择**必须与学习率联合调**，否则会得到"批量越小越差"的假结论。

> **时间预算机制**：`train.time_budget_seconds` 会在超过预算时提前结束训练，
> 并在 `*_run.json` 写入 `budget_exhausted: true` 与实际轮数；汇总表相应
> 标注"（含预算截断）"。这保证"没跑满"这件事被如实记录，
> 而不是伪装成跑满 80 轮的结果。

   "μ=0 + lr=0.05"（步长居中）是未覆盖的第三臂，列入后续工作（§10）。

|---|---|---|---|---|

逐项可视化确认：只有**几何增强**会把字符整体挪位、缩放并引入旋转带来的
黑色填充边，其余各项都保持字符可读。

> **测量时的坑**：增强函数期望输入在 `[0,1]`。第一次诊断误传了 0–255，
> 结果"未增强"这一行的与原图差异竟然是 86.02/255——**如果没注意到这个
> 自相矛盾的数字，就会得出"增强全是噪声"的错误结论**。归一化到 `[0,1]`
> 后 `none` 档位的差异正好是 0.0000，可作为该诊断自洽性的校验点。

**原因分析**：本模型是**全连接 MLP，没有任何平移/尺度不变性**。输入是
4096 维像素按固定位置展平，第 k 个像素对应固定的输入单元。几何增强把
字符挪到训练分布之外的像素位置上，同一个字符类在不同样本里落在不同单元，
模型必须"同时学会所有位移"——这对 MLP 而言不是正则而是标签噪声。因此
数据越增强、训练越难，最终连训练集都拟合不好（`aug_strong` 训练字符仅
59.7%（3 种子均值；s42 单种子 60.2%），是典型欠拟合）。

**这正好解释了为什么增强在 CNN 上有效而在本架构上无效**：CNN 的卷积核
共享权重，天然具备平移等变性，位移后的样本落在同一组特征上，因此几何
增强是在扩充有效样本；MLP 不具备这一性质。（本项目按 §0.3 不使用 CNN，
因此这个负结果是架构限制的直接体现，而非调参失误。）

**注意**：`aug_none` 的验证集指标（98.27%）与测试集（98.28%）几乎相同，
但训练集是 100.00%，说明存在轻微过拟合；只是在本数据规模下，
"不增强"带来的拟合收益远大于过拟合损失。

## 8. 跨域差距分析（§0.4 要求的第 4 条）

本节说明真实域训练出的模型在**合成域测试集**上的表现及其来源。合成域已
切换为外部生成器（§2.4），当前口径下的量级是：

| 模型 | 同分布 test 字符 | 合成域 synth 字符 | 差距 |
|---|---|---|---|
| 基线（共享六头 + 弱增强，3 种子均值） | 86.82 ± 1.76% | **43.26 ± 3.05%** | **−43.6 pt** |
| E1 独立六头（3 种子均值） | 94.30 ± 0.48% | **66.92 ± 0.82%** | **−27.4 pt** |
| E7 `aug_none`（最优同分布） | 98.36 ± 0.08% | **44.50 ± 0.72%** | **−53.9 pt** |

参考水平：34 类随机猜测 `1/34 ≈ 2.9%`；"逐位总出合成集里最高频的那个字符"
= **4.05%**；把**训练集**逐位众数直接搬到合成集 = **3.12%**。因此
**模型在合成域上远高于平凡基线（43% vs 4%），但仍与同分布差 40 个百分点
以上**——既不是"完全失效"，也不是"已经迁移成功"。

> **与旧版合成集的对比（口径已作废，必须说明）**：早期版本用本项目内置的
> PIL 渲染器生成合成集，同一基线的合成域字符准确率只有 **5.6%**（≈乱猜），
> 并据此得出"跨域差距极大、增强/容量都解决不了"的结论。换成外部生成器后
> 该量级变为 **41.6%**，**旧结论已作废**。差别来自两版合成集的构造（见 §8.3），
> 这正是"合成测试集的构造方式直接决定测出来的域差大小"的实例。

### 8.3 差距来源：合成域与本域的外观差异

两版合成集同样的真实域模型测出 5.6% 与 41.6%（基线）两种结果，原因在
**合成图与真实图的接近程度**。当前合成集的构造（§2.4）与旧版的关键差别：

| 维度 | 旧版内置渲染器 | 当前外部生成器 |
|---|---|---|
| 字形素材 | 系统 CJK 字体渲染 | **上游位图字形素材（由实拍车牌裁切而来）** |
| 版式 | 4 种（蓝/黄/白/绿底） | 1 种蓝底模板（`plate_background_use`） |
| 字符间距/位置 | 与真实域同一套几何比例 | 上游模板固定 x 位置，与真实域接近但非同一套 |
| 扰动链 | 本项目自定（抖动/噪声） | 上游 `jittering_color/add_noise/jittering_blur/jittering_scale` |

也就是说：**新合成集在"字形外观"上比旧版更接近真实域，模型自然迁移得更好**。
剩余差距的两域统计对比（数值来自 `reports/logs/domain_gap.json`）：

| 维度 | 真实（CCPD-Base） | 合成域（generator_repo） |
|---|---|---|
| 成像方式 | 实拍照片（压缩、运动模糊、光照不均、反光） | 位图字形贴到模板 + 颜色/噪声/模糊/缩放扰动 |
| 原始像素均值 | 108.2 | **82.1**（蓝底更暗） |
| 标准化后均值 | +0.015σ | **−0.449σ** |
| 标准化后标准差 | 0.982 | 1.034 |

模型在 9000 张真实图上已达到训练集 88–91% 的拟合水平（仍处欠拟合区，见
§7.7），在合成域上则保留 40% 以上的字符判别力。**这两点合起来说明：差距
既包含"外观链路不同"的成分，也包含"模型容量/位置特异表征不足"的成分**——
后者由 E1 直接证明：把参数量从 1.10M 提到 6.35M（独立六头），合成域字符
准确率从 43.26% 提到 66.92%（+23.7 pt）。§8 开头引用的"旧版合成集上两架构
都只有 5–6%"因此**不能**再支持"跨域差距与容量无关"这一说法。

### 8.4 顺带发现并修复的一个真 bug（值得记录）

独立评测脚本最初写成：

```python
params = build_model(...)     # 随机初始化
params.load(ckpt)             # ← 返回值被丢弃
return params                 # 返回的仍是随机权重！
```

`Params.load` 是 **classmethod，返回 `(Params, extra)`**，不是就地载入。
后果是评测用的是随机权重，真实测试集字符准确率只有 **3.10%**，而训练脚本
汇报 86.7%。**这是靠"同一指标两条独立路径交叉核对"才发现的**——如果只信
一条路径，会得到一个完全错误（而且看起来"合理"）的结论。

修复后独立评测与训练脚本的数字**完全一致**（86.73% / 42.60%），
并在载入时增加了结构校验（`head_dims` / `arch` / `hidden_dim` / `input_dim`
与配置不符就直接报错，而不是静默使用不匹配的权重）。

按 §0.4 第 4 条要求，需要能解释三类测试集之间的性能差异。以最优同分布
模型（E7 `aug_none`，seed=42）为例：

| 测试集 | 字符准确率 | 整牌准确率 | 相对同分布 |
|---|---|---|---|
| 同分布 test | 98.28% | 91.35% | 基准 |
| 强扰动 hard_test | 72.55% | 32.05% | **−25.7 / −59.3 个百分点** |
| 合成域 synth_test | 43.67% | 0.80% | **−54.6 / −90.6 个百分点** |

**差异来源拆解**：

* **强扰动集（−25.7 pt）**：与同分布**共享同样的成像风格与字形**，差异只在
  模糊/旋转/光照/天气等退化。模型见过类似的退化（弱增强里含模糊与噪声），
  所以只掉 25 个百分点，属于"可控退化"。
* **合成域（−54.6 pt 字符 / −90.6 pt 整牌）**：共享的是**字符内容**，差异在
  **整条成像链路与字形素材**（§8.3）。模型仍保留 43.67% 的字符判别力（远高于
  平凡基线 4.05%），但整牌几乎归零——这不是另一个机制，而是**整牌是"六位
  全对"的合取指标**：字符级 43.67% 的独立错误率在 6 位上累积，整牌上界约
  `0.4367⁶ ≈ 0.7%`，与实测 0.80% 一致。**跨域时应当以字符准确率为主指标，
  整牌准确率会放大差距**。
* **结论仍然成立但幅度不同**：**"见没见过这种成像风格"比"字符难不难"重要
  得多**——强扰动（−25.7 pt）远小于跨域（−54.6 pt）；E7 里强增强最差也同向。
  但改用外部生成器后，"合成域≈乱猜"已不成立，跨域差距的量级**取决于合成集
  与真实域的接近程度**（§8.3），这本身就是本节最重要的一条结论。
* **补充警示**：合成域上的变体排序与同分布**并不一致**。同分布最优是
  `aug_none`（98.28%），而合成域最优是 **E1 独立架构（66.92%）**，比
  `aug_none`（44.50%）高 22 pt。原因是独立架构给每个位置各自的特征空间，
  对"字形间距/外观在本域与合成域间的差异"容忍度更高。因此**不能用单一合成域
  指标给模型排序**，必须与同分布指标并列解读。

## 10. 局限与后续改进

1. **数据规模**：训练集只有 9000（受 `ccpd_base` 子集规模限制）。
   指向完整 CCPD2019 并恢复 `train_size: 20000+` 后，预计同分布整牌准确率
   还有提升空间。
2. **架构**：MLP 缺少空间不变性，是本项目多个现象（增强反而变差、整牌
   准确率偏低、第 6 位最弱）的共同根源。规格 §0.3 明确禁止 CNN，因此这是
   架构约束下的结果，不是调参可以消除的。
3. **增强策略**：若必须用增强，应把几何部分大幅收窄（例如旋转 ±2°、
   缩放 0.95–1.05），或干脆只用光度增强；E7 已经量化了当前的代价。
4. **跨域（已完成的改动与剩余工作）**：本阶段已按要求把合成域测试集换成
   外部开源生成器（§2.4），跨域差距从旧版合成集上的"≈乱猜"变为
   **−53.9 ~ −27.4 pt**（取决于架构）。剩余可做的方向：
   （a）**域随机化**——把该生成器也用于训练时的离线增广（不同字体/底色/
   模板 + 其扰动链），看合成域与强扰动是否同时受益；
   （b）**合成域口径的敏感性**——当前结论已经表明"合成集怎么造直接决定测出
   的域差"（5.6% → 41.6%），值得把 2–3 个不同构造的合成集并列报告，
   避免单一合成集给出误导性的跨域结论；
   （c）合成域上的架构排序与同分布不同（§8.5），需要更多架构臂来确认
   "位置特异容量 → 跨域鲁棒性"这一假说。
5. **合成域可学性对照未在本轮重跑**：按"只重测、不重训"的约束，
   `train/diag_synth_learnability.py`（在合成域上训练小模型）未重跑，
   §8.2 因此只保留不依赖训练的自洽性证据；如需补齐，命令见 §8.2。
6. **实验覆盖**：E1–E9 全部完成（E2/E5/E6/E8/E9 的结果见 §7.2/§7.6/§7.7/
   §7.9/§7.10）。后续可考虑的方向是：给 E2 补上"lr 与激活函数联合扫参"
   （§7.2 的探针只做了 lr=0.01 一个点）、给 E4 补上学习率随批量的缩放律
   （`lr ∝ 1/√B`）对照。
